# F1 · Projetos

## Problema

Para conduzir um projeto, o Metri precisa saber qual repositório é e se ele já usa o método. No primeiro marco, o único projeto é o próprio Metri, que chega com o método instalado e com o plano feito à mão.

## Solução

O servidor do Metri escuta só em `127.0.0.1` e exige um token em toda chamada; uma aba de antes de um reinício diz como abrir o Metri de novo. O humano abre no Metri um repositório git que já usa o método. O Metri confere se a pasta é um repositório git, se tem branch padrão e se tem o método instalado, e recusa com o motivo quando falta alguma dessas coisas. O projeto aberto entra na lista de projetos, com a pasta, a branch padrão e a versão do método, e nenhum arquivo do repositório é tocado. Ao entrar no projeto, a Visão geral mostra um próximo passo só e onde o trabalho está.

## Casos de uso

- UC1.1 · Abrir um projeto que já usa o método
- UC1.2 · Ver a visão geral do projeto
- UC1.3 · Entrar no Metri pela partida

## Decisões de implementação

- Acesso, pelo contrato da S1 e pelo ADR-0002 (pontos 1, 2 e 7): o token é `randomBytes(32)` em base64url, novo a cada partida, guardado só na memória e no arquivo de execução. A partida abre `http://127.0.0.1:<porta>/#token=<token>`; a página manda o token em `POST /api/session`, que devolve o cookie de sessão `HttpOnly`, `SameSite=Strict` e `Path=/`, e apaga o fragmento com `history.replaceState`. CLI e agentes usam `Authorization: Bearer`. Uma guarda única, antes do estático e de `/api` e no `upgrade` do WebSocket, confere o `Host` (`127.0.0.1:<porta>` ou `localhost:<porta>`, senão 403), o `Origin` quando vem (igual a uma dessas origens; `null` recusado; obrigatório no upgrade sem `Authorization`) e a credencial, em tempo constante. É o caminho do T3 Code (`pingdotgg/t3code@a4c9494b:apps/server/src/auth/EnvironmentAuth.ts:1143-1190`), com a checagem de `Host` do Jupyter (`jupyter-server/jupyter_server@f8169d72:jupyter_server/serverapp.py:1355-1366`) e do sidecar do Conductor (0.90.1, `conductor-runtime`).
- Fuga do padrão, decidida no Moldar: a aba de antes do reinício não continua autenticada; ela diz que o Metri reiniciou. T3 Code e Jupyter guardam o segredo do cookie para a aba sobreviver.
- Cabeçalhos de segurança, que `general/http-surface` delega ao projeto: pelo `helmet`, em toda resposta, a CSP `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; font-src 'self' data:; connect-src 'self'; frame-src http://127.0.0.1:* http://localhost:*; frame-ancestors 'none'; base-uri 'self'; form-action 'self'; object-src 'none'`, mais `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy: no-referrer` e COOP e CORP `same-origin`. Sem HSTS e sem `upgrade-insecure-requests`, que o `helmet` liga e que quebram o `localhost` (RFC 6797). O OpenCode manda a CSP em header no HTML servido (`anomalyco/opencode@5d9cd9b2:packages/opencode/src/server/shared/ui.ts:11-102`); um `<meta>` não serviria, porque ignora `frame-ancestors`.
- Módulo `projects`, com o agregado `Project`: id, pasta real, branch padrão, versão do método e data de abertura. A conferência da BR1 só lê: `git rev-parse`, `git symbolic-ref refs/remotes/origin/HEAD` e a versão do pacote do método instalado.
- A Visão geral (UC1.2) é uma query de exibição sobre a projeção do plano (S5), a Inbox (S6) e o Scheduler: o próximo passo pela BR78, a entrega das features `now`, as slices em construção, a frontier com o motivo de cada ticket parado, as lacunas, as propostas de padrão e a Fog.

## Decisões de teste

- Acesso: o e2e HTTP e WebSocket do app-api montado pela função de partida, variando `Host`, `Origin` e credencial; e o e2e do navegador, que entra pela URL da partida e confere a barra de endereço sem o token.
- Projetos: a rota de abrir projeto contra repositórios git criados no teste (sem git, sem branch padrão, sem `.metri/`, sem o pacote), conferindo o `git status` depois.
- Visão geral: a rota da query de exibição com um plano de fixture.

## Fora de escopo

- Criar projeto a partir do starter e começar o método num repositório com código (F21).
- Remover um projeto da lista.

## Notas

- Abordagem descartada: os três casos de criação de projeto já no primeiro marco (pasta vazia com starter, repositório com código, pasta sem git). Rodaria o `metri init` e o `pnpm install` de dentro do app para casos que só um usuário de fora tem.
- Abordagem descartada: sem tela de projetos, com um projeto por servidor. A tela e o registro de vários projetos voltariam no `beta` como mudança de forma.
- No primeiro marco, o Metri que conduz roda de uma cópia fixa, separada do checkout que ele constrói (ADR-0008).
