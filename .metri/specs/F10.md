# F10 · Runs e eventos

## Problema

Um agente trabalhando é uma caixa-preta: o humano não vê o que ele faz, não sabe se parou há uma hora e perde o fio quando o servidor reinicia. Para aprovar uma tela, o humano precisa ver o app rodando, sem misturar com o checkout em que ele mesmo trabalha.

## Solução

A tela do Run mostra a conversa ao vivo, montada dos eventos que o Metri grava antes de mostrar. Se o servidor reinicia, o Run é retomado pela sessão do harness ou fica falho com aviso. Os subagentes aparecem dentro da conversa do Run que os disparou, e o custo de cada Run é uma estimativa feita pelo Metri. Um Run sem evento por muito tempo, ou repetindo a mesma chamada, gera um aviso na Inbox, e o estado dele não muda sozinho. O humano manda mensagem a um Run, interrompe o turno ou o cancela. A lista de Runs mostra todos, com filtros. Antes de cada migration, o Metri copia o banco e confere a cópia, e um comando restaura uma cópia com o servidor parado. O Preview sobe o app do Workspace de um Run ou, para a branch da slice em aceite e a branch padrão, num Workspace próprio, e o mostra em desktop e mobile.

## Casos de uso

- UC10.1 · Acompanhar um Run
- UC10.2 · Ver o app rodando
- UC10.3 · Restaurar o banco a partir da cópia de uma migration

## Notas

- Abordagem descartada: sem o aviso de Run travado e sem os Previews da branch padrão e da slice. No primeiro marco, o humano deixa o Metri rodando e sai, e é vendo a slice rodando que ele a aprova.
- Abordagem descartada: o mapa de Runs já no primeiro marco. Com um ticket por vez no projeto, o mapa vira uma linha reta; como cada Run grava o pai, ele entra na F13 sem retrabalho.
- Abordagem descartada: OpenTelemetry no servidor local. Nenhuma ferramenta do mercado usa OTel como fonte das telas, e OpenCode, Kilo Code e T3 Code só exportam por OTLP com um endpoint configurado. O registro de eventos é a fonte das telas, e o log do servidor é o do método. Um arquivo de log com rotação entra no `beta`, com a casca desktop, pelo log estruturado sob demanda. O Metri não liga o OpenTelemetry dos harnesses.
- Abordagem descartada: a conversa só no histórico do harness. Contraria o princípio de experiência "Agente é função", que monta a conversa dos eventos.
