# F4 · Moldar

## Problema

Uma iniciativa começa vaga, e os documentos que a definem (produto, linguagem, design, specs, decisões) nascem de uma entrevista longa com o humano. Feita à mão com um agente, essa entrevista some quando a conversa acaba, e nada impede o agente de escrever fora do lugar ou de criar trabalho antes de a direção ser aprovada.

## Solução

Uma iniciativa abre um Run de Moldar num Workspace próprio, `plan/<n>`; recusar o portão de direção a encerra. O agente pergunta em rodadas, e o Run espera a resposta sem gastar tokens. Ele escreve PRODUCT, CONTEXT, DESIGN, ADRs e as specs no git do Workspace, e cria os UCs em rascunho pelo Metri. Um painel ao lado da conversa mostra os arquivos do `plan/<n>` mudando e as propostas feitas. Antes do portão de direção, o crítico sem contexto lê o que foi escrito. O portão mostra os três blocos e o diff dos documentos.

## Casos de uso

- UC4.1 · Moldar uma iniciativa
- UC4.2 · Resolver o portão de direção

## Decisões de implementação

- O Moldar é um Run de papel `shaper`, com a skill de moldar (T10.2), no Workspace `plan/<n>` (o próximo número do projeto, guardado no banco), com o preset padrão.
- O painel de arquivos mostra o diff do `plan/<n>` contra a branch padrão, refeito a cada commit do Run, e as propostas, pelo registro de eventos.
- A espera pela resposta (BR46) usa o `ask_human` sem prender a chamada (ADR-0014): o turno termina, e o Run fica esperando você.
- O crítico é um Run de papel `critic` (T10.3), somente leitura, que recebe só o produto, as specs e os UCs em rascunho.

| Estado da iniciativa | Entra quando |
| --- | --- |
| moldando | o pedido abre o Run de Moldar, ou o humano pede ajuste no portão de direção |
| portão de direção | o Moldar entrega, com o crítico feito |
| planejando | a direção é aprovada, ou o humano pede ajuste no portão de plano |
| portão de plano | o Look across entrega, com o crítico feito |
| aprovada | o portão de plano é aprovado, e o `plan/<n>` entra na fila |
| integrada | o merge do `plan/<n>` entra na branch padrão |
| encerrada | o humano recusa um dos dois portões; os UCs em rascunho dela ficam `cancelled` |

## Decisões de teste

- Abrir a iniciativa e resolver o portão de direção, com o Moldar do driver falso roteirizado escrevendo no `plan/<n>` e chamando `propose`; o e2e do painel e do portão.

## Fora de escopo

- Moldar sem Workspace, direto na branch padrão.

## Notas

- Abordagem descartada: o Run de Moldar sem o painel dos arquivos. O humano responderia às perguntas sem ver os documentos nascendo.
- Abordagem descartada: o Moldar continuar no Claude Code, à mão, com o Metri só recebendo a branch. O primeiro marco não cumpriria o próprio critério de saída, em que as slices seguintes são planejadas dentro do Metri.
