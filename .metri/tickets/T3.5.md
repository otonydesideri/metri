# T3.5 · Padrão do Run

## O que entrega

O Run: o agregado com os estados da BR74, a abertura da sessão do harness pelo contrato dos drivers (S2), a gravação dos eventos normalizados no registro e o Run de onde ele veio. A regra do projeto, com o exemplo canônico: um Run aberto com o driver falso, do começo ao fim.

## Critérios

- [ ] A regra do projeto existe, com o exemplo canônico e o check em `enforced_by`.
- [ ] Um Run aberto com o driver falso passa por preparando, rodando e concluído, e cada evento do driver fica no registro, na ordem, com a sequência do Run.
- [ ] Cada Run grava o papel, o alvo, o modelo, a Policy com que abriu e o Run de onde veio, quando há um.
- [ ] Um erro do driver no meio do turno deixa o Run falho, com o motivo, e nenhum evento a menos do que o driver mandou.
