# UC10.1 · Acompanhar um Run

Como humano, quero acompanhar ao vivo o que um agente faz e ser avisado quando ele trava, para intervir antes de perder horas.

## Regras de negócio

- BR17: Todo evento é gravado antes de ir para a tela, e o registro de eventos só cresce.
- BR18: O aviso de Run travado não muda o estado do Run; quem decide é o humano.
- BR61: O custo de um Run é estimado pelo Metri a partir dos tokens e de uma tabela de preços, e aparece sempre como estimativa; o valor que o harness informa é só referência.
- BR100: Num Run, o humano manda mensagem, interrompe o turno ou cancela. A mensagem com o turno em andamento espera o fim dele, com a opção de interromper e enviar; interromper para o turno e mantém a sessão do harness para retomar; cancelar encerra o Run, pede sempre o motivo e, num Run de ticket, devolve o ticket a `open` com o motivo nas notas.
- BR74: Um Run está num destes estados: na fila, preparando, rodando, esperando você, verificando, concluído, falhou, sem orçamento, interrompido ou cancelado.

## Critérios

- [ ] Com um Run ativo, cada evento aparece na tela em até 300 ms depois de chegar do agente, medido no teste de ponta a ponta.
- [ ] Tela: a tela do Run mostra mensagens, chamadas de ferramenta, comandos e diffs.
- [ ] Uma mensagem enviada com o turno em andamento espera o fim do turno; "interromper e enviar" para o turno e manda a mensagem na hora.
- [ ] Interromper para o turno, o Run fica esperando o humano, e a próxima mensagem retoma na mesma sessão do harness.
- [ ] Cancelar sem motivo é recusado; com motivo, o Run fica cancelado, e num Run de ticket o ticket volta a `open`, com o motivo nas notas.
- [ ] Com o servidor reiniciado durante um Run, o Run fica interrompido e é retomado pela mesma sessão do harness; se a retomada falha, ele fica falho, com aviso na Inbox.
- [ ] Com um Run rodando sem evento por 10 minutos, ou com a mesma chamada de ferramenta repetida 5 vezes seguidas, a Inbox recebe o aviso de Run travado, e o estado do Run não muda. Um Run esperando o humano e o Coordinator sem pedido em andamento não geram o aviso.
- [ ] O aviso de Run travado leva à tela do Run e oferece cancelá-lo; num Run de ticket, cancelar devolve o ticket a `open`, com o motivo.
- [ ] Cada Run grava o Run de onde veio, quando há um: o Coordinator, para o Run que um pedido abre, e o Run anterior do mesmo ticket, para o seguinte.
- [ ] Os subagentes que o harness dispara aparecem dentro da conversa do Run que os disparou (ADR-0004).
- [ ] Na retomada, o Metri reenvia as opções da sessão do harness (Policy, servidores MCP e modo de permissão), que o harness não restaura.
- [ ] Derrubar o processo do servidor no meio de um Run não perde nenhum evento que já tinha aparecido na tela.
- [ ] Tela: a lista de Runs mostra papel, alvo, harness e modelo, estado em texto, iteração, custo, início, fim e motivo de parada, com filtros.

## Notas

- A fonte da tabela de preços e como ela se atualiza não estão decididas; este ticket decide. Os 300 ms dependem do streaming parcial do SDK (`includePartialMessages`), a confirmar neste ticket.
- A retomada pelo id da sessão depois de reiniciar o processo é documentada; uma ferramenta que rodava na queda aparece cortada e não roda de novo. O harness guarda os transcripts por 30 dias por padrão (`cleanupPeriodDays`) (https://code.claude.com/docs/en/agent-sdk/sessions; https://code.claude.com/docs/en/sessions).
