# UC10.3 · Restaurar o banco a partir da cópia de uma migration

Como humano, quero que o Metri copie o banco antes de cada migration e me deixe restaurar uma cópia, para não perder o plano se uma atualização der errado.

## Regras de negócio

- BR96: Antes de aplicar migrations, o Metri copia o banco e confere a cópia com o `quick_check`. Com a cópia inválida, a partida é abortada, e nenhuma migration roda. Ficam as 3 cópias de migration mais recentes.
- BR97: A restauração só roda com o servidor parado: confere a cópia escolhida, guarda o banco atual e troca.

## Critérios

- [ ] Com uma migration pendente, a partida copia o banco, a cópia passa no `quick_check`, e só então a migration roda.
- [ ] Com a cópia falhando no `quick_check`, a partida é abortada com o motivo, e o banco fica como estava.
- [ ] Depois de quatro partidas com migration, ficam só as 3 cópias mais recentes.
- [ ] Com o servidor rodando, o comando de restaurar recusa e diz para parar o servidor.
- [ ] Restaurar confere a cópia e guarda o banco atual ao lado; na partida seguinte, o Metri abre com o conteúdo da cópia.

## Notas

- No mercado, o T3 Code copia o banco antes de atualizar o servidor, cancela a atualização se a cópia falhar e restaura se a versão nova falhar (`pingdotgg/t3code@4dbc0129:apps/server/src/serviceLauncher.ts:66-73,109-177`).
