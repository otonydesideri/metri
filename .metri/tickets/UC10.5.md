# UC10.5 · Retomar um Run depois de reiniciar

Como humano, quero que um Run em andamento continue depois que o servidor reinicia, para não perder o trabalho do agente.

## Regras de negócio

- BR105: Na partida, antes de o Scheduler voltar, todo Run num estado ativo fica interrompido. O Metri o retoma pela mesma sessão do harness e, se a retomada falha, o marca como falho, com aviso na Inbox.

## Critérios

- [ ] Com o servidor reiniciado durante um Run, o Run fica interrompido e é retomado pela mesma sessão do harness; se a retomada falha, ele fica falho, com aviso na Inbox.
- [ ] Num Run de ticket cuja retomada falha, o ticket fica `blocked` com o motivo `human`, como antes desta retomada existir.
- [ ] Na retomada, o Metri reenvia as opções da sessão do harness (Policy, servidores MCP e modo de permissão), que o harness não restaura, com um token novo para o Run.
- [ ] Uma aprovação de ferramenta que esperava resposta quando o servidor caiu aparece expirada depois da partida.
- [ ] Depois de retomar a sessão do harness, as liberações "permitir sempre neste Run" continuam valendo.

## Notas

- A retomada pelo id da sessão depois de reiniciar o processo é documentada; uma ferramenta que rodava na queda aparece cortada e não roda de novo. O harness guarda os transcripts por 30 dias por padrão (`cleanupPeriodDays`) (https://code.claude.com/docs/en/agent-sdk/sessions; https://code.claude.com/docs/en/sessions).
