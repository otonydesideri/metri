# T4.2 · Padrão de Workspace

## O que entrega

O Workspace de um alvo: a worktree na branch dele, a faixa de 10 portas reservada no banco, a pasta temporária, os arquivos ignorados que a lista do projeto pede e os scripts do projeto (setup, run e archive) com as variáveis do Metri (ADR-0010). A regra do projeto, com o exemplo canônico, e os scripts do próprio repositório do Metri.

## Critérios

- [ ] A regra do projeto existe, com o exemplo canônico e o check em `enforced_by`.
- [ ] Preparar o Workspace de um ticket cria a worktree em `ticket/<id>` a partir da branch da slice (criada da branch padrão quando falta), copia os arquivos da lista e roda o setup com `METRI_ROOT_PATH`, `METRI_WORKSPACE_PATH`, `METRI_WORKSPACE_ID`, `METRI_PORT` e `E2E_PORT`.
- [ ] Dois Workspaces nunca recebem a mesma porta, e a reserva pula a faixa com uma porta ocupada.
- [ ] Arquivar encerra os processos do Workspace, roda o archive, apaga a worktree e libera a faixa; se o archive falha, o Workspace fica, com a saída guardada.
- [ ] O repositório do Metri tem os scripts do projeto e a lista de arquivos ignorados, e o setup deixa um Workspace onde o `pnpm verify` passa.
